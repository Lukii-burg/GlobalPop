# Team Code of Conduct

## 1. Purpose & Core Values
This Code of Conduct outlines the standards, expectations, and rules for all members working on the **DevOps Coursework Project (SET09803)**. Our goal is to maintain a professional, inclusive, and collaborative environment that enables every team member to contribute effectively toward delivering a high-quality product.

All team members agree to uphold the following values:
* **Respect & Professionalism:** Treat all team members with kindness, dignity, and active listening.
* **Constructive Communication:** Communicate clearly, give actionable feedback, and address issues early.
* **Inclusivity & Collaboration:** Encourage contributions from everyone and value diverse perspectives.
* **Accountability:** Take ownership of assigned tasks, meet deadlines, and contribute equitably to team success.

---

## 2. Team Expectations & Responsibilities

### Scrum & Project Management Practices
* **Active Participation:** Members are expected to participate in all Sprint Planning, Standups, and Review meetings.
* **Task Ownership:** Tasks defined as **User Stories** on the project board (GitHub Projects / Zube.io) must be regularly updated to reflect true progress.
* **Equal Contribution:** Each member must contribute consistently across both Code Review assessment points (aiming for equal contribution as reflected in the peer review spreadsheet).

### Technical & Git Flow Workflows
* **Git Standards:** All team members must adhere strictly to the project's GitFlow workflow (`master`, `develop`, feature, and `release` branches).
* **Code Quality:** All code submitted via Pull Requests (PRs) must be formatted, clean, commented, and verified to build with Maven before requesting review.
* **Code Reviews:** No code should be merged into `develop` or `master` without peer review approval.

---

## 3. Decision-Making & Conflict Resolution

### Decision-Making
* Project decisions should be made transparently, inclusively, and collaboratively.
* Members are encouraged to express technical opinions respectfully and evaluate trade-offs together.
* If consensus cannot be reached, decisions will be resolved by majority vote or delegated to the designated Scrum Lead / Project Lead.

### Conflict Resolution
1. **Direct Communication:** Address initial concerns or misunderstandings directly and constructively with the involved member(s). Focus on the issue, not the person.
2. **Team Mediation:** If unresolved, escalate the issue to the Scrum/Project Lead for informal mediation.
3. **Lecturer Escalation:** If an internal resolution cannot be reached, the issue will be brought to the module teaching team (Kevin Sim) for formal guidance.

---

## 4. Unacceptable Behavior
Unacceptable behavior includes, but is not limited to:
* Harassment, bullying, discrimination, or offensive language in any communication channel.
* Persistent failure to complete agreed-upon Sprint tasks or communicate availability.
* Deliberately disrupting project progress, ignoring Git/branching standards, or committing directly to `master`.
* Academic misconduct or non-contribution to group deliverables.

---

## 5. Acknowledgment & Agreement

By working on this project repository and participating in team activities, all members agree to abide by this Code of Conduct and support a productive, fair, and high-performing team environment.
